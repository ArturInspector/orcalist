## План по тестам и окружению

1. **Бэкенд: базовая подготовка**
   - Установить `uv` или стандартный `python -m venv` для создания изолированного окружения, целевая версия Python 3.11.
   - Зафиксировать зависимости в `requirements.txt`/`requirements-dev.txt` (FastAPI, httpx, pytest, pytest-asyncio, respx, coverage, solana-py).
   - Настроить `.env.devnet` с `SOLANA_RPC_URL`, `CHARGE_TO`, `FIXED_CHARGE_SOL`; в тестах загружать через `python-dotenv`.

2. **Юнит-тесты FastAPI**
   - Покрыть чистые хелперы: `_ensure_main_fields`, `_append_fixed_charge`, сериализацию `_b64`.
   - Мокать RPC-клиент `Client` через `unittest.mock` или `respx` для проверки вызова `recent_blockhash` и корректной обработки ошибок.
   - Проверить валидацию входных данных Pydantic-моделей (валидные/невалидные ключи, отрицательные суммы).

3. **Интеграционные тесты FastAPI**
   - Использовать `pytest` + `httpx.AsyncClient` с `lifespan='on'` для запуска приложения в тестах.
   - Для `/api/proceed` и `/api/listing` подготовить сценарии с моком RPC (позитивный, ошибка RPC, некорректные входные данные).
   - Снимок логирования: проверять, что мы логируем RPC-метод и подпись транзакции без приватных данных (можно перехватывать `caplog`).

4. **Интеграция c Devnet**
   - Отдельная директория `tests/devnet/`, префикс `test_<operation>_devnet.py`.
   - Фикстуры: создание `AsyncClient` FastAPI + настоящий `Client(RPC_URL)`.
   - Сценарии: создание токена (Token-2022) с ограниченным количеством вызовов; проверка `spl-token display` через MCP (можно обернуть команду в fixture и запускать условно `--run-devnet`).
   - Тяжёлые тесты помечать `@pytest.mark.devnet` и включать только по требованию (`pytest -m devnet`).

5. **Фронтенд**
   - В каталоге `soltoken-frontend` использовать `pnpm` или `npm` (предпочтительно `pnpm`) для установки зависимостей.
   - Настроить `.env.development` с указанием адреса бэкенда (например, `VITE_API_URL=http://localhost:8000`).
   - Для автотестов фронта позже подключить Playwright, но сейчас минимально — smoke-тесты руками после сборки (`pnpm dev`).

6. **Запуск сервисов**
   - Бэкенд: `uvicorn main:app --reload --host 0.0.0.0 --port 8000`, загрузка `.env.devnet` перед стартом.
   - Фронтенд: `pnpm dev --host 0.0.0.0 --port 3000`, проксирование API на 8000.
   - Документация: добавить раздел в `docs/architecture.md` с описанием тестового пайплайна и переменных окружения.

7. **Anchorpy**
   - Для текущих задач Anchor-программа не используется, поэтому `anchorpy` не даёт преимущества; для тестов вокруг SPL Token-2022 достаточно `solana-py` + `spl.token.async`. Anchorpy полезнее при тестировании кастомных Anchor-программ.

8. **Дальнейшие шаги**
   - Внедрить отчёты покрытия (`pytest --cov=main --cov=utils`).
   - Автоматизировать проверку форматирования (ruff/mypy) в CI.
   - Добавить запуск devnet-тестов и MCP-валидаторов в отдельный GitHub Actions workflow.
